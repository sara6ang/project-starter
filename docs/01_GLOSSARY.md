# 📖 PM 용어 사전

> "그게 뭐예요?" 소리 나올 때 바로 펴서 보여주는 용도. 어려운 정의 대신 비유로 설명.
> `docs/` 공유 폴더에 두고, 팀원 아무나 헷갈리면 이 파일부터 보게 하기.

---

## 1. 방향을 정하는 용어

### PRD (Product Requirements Document)
**"뭘 만들지 정리한 계약서."** 어떤 기능이 왜 필요하고, 뭐가 스코프 안/밖인지 적어둔 문서.
→ Tongss에서는 `docs/02_PRD.md`.

### Scope (스코프)
**"이번엔 여기까지만."** 이번 프로젝트/스프린트에서 만들 것과 안 만들 것의 경계선.
- "스코프 안(In)": 이번에 만든다
- "스코프 밖(Out)": 좋은 아이디어지만 지금은 안 만든다 (나중에 08_DECISIONS에 왜 뺐는지 기록)

### MVP (Minimum Viable Product)
**"제일 작게 굴러가는 버전."** 다 갖추지 않아도, 핵심 가치 하나는 실제로 검증할 수 있는 최소 형태.
→ Pepper's Oven이 "메뉴 하나만 파는 가게"였던 이유가 이거.

### 로드맵 (Roadmap)
**"언제 뭘 할지 큰 그림."** 주차별/분기별로 "언제쯤 이게 나온다"를 보여주는 일정표.
Sprint보다 훨씬 크고 느슨한 단위.

### North Star (노스스타)
**"우리가 뭘 위해 이걸 만드는지, 한 문장."** 의견이 갈릴 때 다시 돌아가는 기준점.
→ Tongss의 "Build something worth showing."

### 페르소나 (Persona)
**"가상의 대표 사용자 한 명."** "F&B 사장님", "매장 직원" 같은, 실제 사람은 아니지만
그 그룹을 대표하는 캐릭터. 기능 만들 때 "이 사람이라면 좋아할까?"로 판단 기준 삼음.

## 2. 진행을 관리하는 용어

### Sprint (스프린트)
**"1~2주짜리 작업 묶음."** 이 기간 안에 뭘 끝내겠다고 미리 정해두고 달리는 단위.
Tongss에서는 "Week 1", "Week 2"가 사실상 스프린트.

### Backlog (백로그)
**"아직 안 한 일 전체 목록."** 지금 당장 안 하지만 언젠가 할 수도 있는 것까지 다 모아둔 창고.
Notion Tasks DB에서 "할 일" 상태에 있는 게 다 백로그.

### Kanban (칸반)
**"할 일 → 하는 중 → 완료, 이렇게 칸으로 나눠서 보는 방식."** Notion의 Board 뷰가 이거.

### 스탠드업 (Standup / Daily Check-in)
**"매일 서서 하는 3분 회의."** "어제 뭐했고, 오늘 뭐하고, 막힌 거 있나"만 짧게 공유.
Tongss는 매일 대신 주 1회 Show & Tell로 대체.

### 회고 (Retrospective / Retro)
**"이번 스프린트 끝나고 돌아보는 시간."** 잘된 것 / 안 된 것 / 다음엔 이렇게 하자를 정리.

### Blocker (블로커)
**"이거 때문에 더 못 나가는 것."** 남이 해결해줘야 내가 다음 단계로 갈 수 있는 상태.
→ Notion "상태=막힘" 필터가 이걸 잡아내는 용도.

### Dependency (디펜던시, 의존관계)
**"A가 끝나야 B를 시작할 수 있다."** 순서가 정해진 일. 예: 데이터 계약 확정(A) 전엔
연동 작업(B) 시작 못 함.

## 3. 일하는 방식에 대한 용어

### Workflow (워크플로우)
**"일이 어떤 순서/규칙으로 굴러가는지."** "기획→설계→개발→QA→배포" 같은 흐름 전체.
Tongss의 `09_TEAM_GUIDE.md`가 이 워크플로우를 정의한 문서.

### Iteration (이터레이션)
**"한 바퀴 돌리는 것."** 완벽하게 만들고 넘어가는 게 아니라, 일단 만들고 → 써보고 → 고치고
→ 또 써보고. 그 한 번의 사이클.

### Release (릴리스)
**"실제로 내놓는 것."** 팀 안에서만 보던 걸 실사용자(또는 데모)에게 처음 보여주는 순간.
→ Demo Day가 사실상 "Release 1.0".

### Feature Freeze (피처 프리즈)
**"이제 새 기능 그만, 있는 거 다듬기만."** 마감 직전에 새로운 걸 더 안 넣기로 선언하는 것.
→ Tongss Final 주(8/31~9/3)가 이거.

### Definition of Done (완료의 정의, DoD)
**"이 정도 되면 끝난 거로 친다"의 기준.** "코드만 짜면 끝"이 아니라, 예를 들면
"테스트 통과 + 문서화 + 리뷰 완료"까지 다 돼야 진짜 완료.

### Acceptance Criteria (수용 기준)
**"이 기능이 성공했다고 인정받으려면 뭘 만족해야 하는지 체크리스트."**
예: "손님이 전화번호 4자리로 검색하면 0.1초 안에 결과가 뜬다" 같은 구체적 조건.

## 4. 사람·역할에 대한 용어

### Stakeholder (이해관계자)
**"이 프로젝트 결과에 영향받거나, 영향을 주는 사람."** 팀원뿐 아니라 멘토, 토스플레이스,
동생의 F&B 팀도 다 이해관계자.

### Owner (오너)
**"이 영역에 대해 최종 결정하는 사람."** "담당자"보다 강한 말 — 오너는 그 영역에서
남 눈치 안 보고 판단 내릴 권한이 있음. (→ `forSara.md` 5번 조직 구조 참고)

### Sign-off (사인오프, 승인)
**"이제 이거 확정이니 더 안 바꾼다는 공식 동의."** 데이터 계약(05_DATA_CONTRACT) 같은
문서에 트랙 리드들이 다 동의하면, 그 이후엔 함부로 안 바꾸는 것.
