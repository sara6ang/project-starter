# 함께 생각해 볼 질문

이 질문들은 **정답을 찾기 위한 질문이 아니라**

Tongss가 어떤 제품인지,
그리고 User 입장에서 무엇이 중요한지 생각해 보기 위한 질문입니다.

---

## Owner (사장)

### Tongss는 어떤 업무를 관리하면 좋을까?

```
ex

- 출근(출석) 확인
- 오픈 · 마감 체크
- 청소 체크리스트
- 재고 확인
- 매뉴얼 확인
- 신규 직원 교육
- 정기 업무(주간/월간) ex.청소, 월말 재고조사 같은 것
```
> 어떤 업무가 매일 반복되고, 시스템으로 관리하면 도움이 될지 함께 생각해 보세요.

### 매뉴얼은 어떻게 하면 가장 쉽게 만들 수 있을까요?

```
ex
- 업종별 매뉴얼 템플릿을 제공한다.
- 질문에 답하며 차근차근 작성한다.
- AI와 대화하며 초안을 만든다.
- 기존 매뉴얼을 복사해 필요한 부분만 수정한다.
```
> 꼭 이 방법일 필요는 없습니다. 사장님이 가장 편한 방법이 무엇일지 함께 생각해 보세요.

### 사장은 어떤 정보를 보면 안심할 수 있을까?

```
ex
- 오늘 누가 출근했는지
- 어떤 업무가 완료됐는지
- 아직 남은 업무는 무엇인지
- 신규 직원이 교육을 어디까지 진행했는지
- 도움이 필요한 직원이 있는지
```

---

## Employee (직원)

### 어떻게 하면 사장님이나 동료에게 묻지 않고도 일을 할 수 있을까?

```
ex
- 오늘 해야 할 일을 순서대로 알려준다.
- 필요한 매뉴얼을 바로 찾을 수 있다.
- 지금 상황에 맞는 매뉴얼을 추천해 준다.
```

### 어떻게 하면 자연스럽게 일을 할 수 있을까?

```
ex
- 해야 할 일을 하나씩 안내해 준다.
- 완료하면 다음 업무를 알려준다.
- 체크리스트를 따라가기만 하면 된다.
- 바쁜 시간에는 꼭 필요한 정보만 보여준다.
```

---

## Tongss Sales

### 어떤 매장을 먼저 도와야 할까?

```
ex
- 최근 직원 교육이 많이 필요한 매장
- 매뉴얼이 오래 업데이트되지 않은 매장
- 체크리스트 수행률이 낮은 매장
- 신규 직원이 많이 들어온 매장
```

### 매장이 Tongss를 잘 활용하고 있는지는 어떻게 알 수 있을까?

```
ex
- 매뉴얼이 꾸준히 업데이트된다.
- 직원들이 매뉴얼을 자주 확인한다.
- 체크리스트 수행률이 높다.
- 신규 직원이 빠르게 적응한다.
```

### 함께 생각해보기

```
ex
- Sales가 고객을 이해하는 데 어떤 데이터가 필요할까요?
- 어떤 데이터가 고객 유치와 고객 유지에 도움이 될까요?
- 반대로, 직원 이름이나 상세 근무 기록처럼 매장 내부 운영 정보는
  Tongss Sales가 아니라 매장 관리자(Admin)가 보는 정보일 수도 있습니다.
```

> 어떤 데이터를 Sales가 보고,
> 어떤 데이터를 매장 관리자(Admin)가 봐야 할지 함께 구분해 보세요.

# 자신이 맡은 역할 이해하기

Tongss는 여러 개의 Repository(프로젝트 폴더)로 나누어 개발합니다.
수요일까지는 아래 질문에 답할 수 있으면 충분합니다.

- 내가 맡은 Repository는 무엇을 만드는 곳일까?
- 왜 이 Repository가 필요할까?

# 지금은 고민하지 않아도 되는 것

이번 프로젝트의 목표는 **Tongss의 핵심 가치를 가장 작은 형태(MVP)로 보여주는 것**입니다.

기능을 많이 만드는 것보다,
**사장님의 반복적인 업무를 어떻게 줄여줄 수 있는지**에 집중해 주세요.

사용자가 어떤 문제를 겪고 있는지 이해하는 것, 그것이 좋은 제품을 만드는 첫걸음입니다.

- CRM 기능
- Authentication
- Salesforce 권한 구현
- 복잡한 Admin 기능
- 세부 UI 디자인
- 성능 및 기술 최적화
- 미래를 위한 확장 기능

# 마지막으로

이번 주의 목표는
**좋은 아이디어를 많이 내는 것**이 아닙니다.

같은 제품을 이해하는 팀은,
많은 기능을 아는 팀보다 훨씬 빠르게 움직일 수 있습니다.
