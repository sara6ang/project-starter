## 0. 한 줄 요약

F&B 매장의 운영 매뉴얼·재고·직원 관리를 한 곳에 모아, 새 직원이 스스로 익히고 사장이 그 상태를 확인할 수 있게 하는 운영 OS.

**Demo Day 성공 기준 (모든 스코프 판단의 최상위 기준):**

> 이대표(사장)가 매뉴얼을 등록한다 → 김스태프(직원)가 TongssApp에서 본다 → 박세일즈(토스, 실무)가 org에서 그 매장의 상태를 확인한다.

이 한 줄이 실제 데이터로 끝까지 흐르면 성공이다. **이 줄에 없는 기능은 스코프가 아니다.**

## 1. 페르소나 ↔ 기능 매핑

01_PERSONAS의 페인포인트를 기능 후보로 직접 연결한다. `[Top]` 표시는 5.5주 안에 반드시 다루는 것, 나머지는 Out 또는 Nice-to-have다.

### 이대표 (사장)
| 페인포인트 | 기능 | 우선순위 |
|---|---|---|
| 같은 말 하루에도 수십 번 반복 | 매뉴얼 등록(5분 이내, 사진+짧은 텍스트) | `[Top]` |
| 신입 교육 스트레스 | 매뉴얼 뷰어 링크 하나로 전달 | `[Top]` |
| 체크리스트가 안 지켜짐 | 오픈/마감 체크리스트 + 완료 여부가 사장에게 보임 | `[Top]` |
| 매뉴얼을 안 읽음 | (콘텐츠 문제 아님 — 김스태프 쪽 UX로 해결) | 연동 |
| 누가 뭘 했는지 모름 | 직원별 학습·체크리스트 완료 상태 대시보드 | `[Top]` |

### 김스태프 (직원)
| 페인포인트 | 기능 | 우선순위 |
|---|---|---|
| 뭘 해야 하는지 모름 | 매뉴얼 뷰어 (역할/상황별 진입) | `[Top]` |
| 물어보기 눈치 보임 | 폰으로 3초 안에 찾는 검색 없는 구조(맥락 기반 노출) | `[Top]` |
| 실수하면 혼남 | (매뉴얼 뷰어로 대응) | 연동 |
| 매뉴얼이 너무 길다 | 한 화면 = 한 동작 원칙, 이미지 중심 | `[Top]` (설계 원칙) |
| — | 재고 실사 입력 (한 손 입력) | `[Top]` |

### 박세일즈 (토스, 실무)
| 페인포인트 | 기능 | 우선순위 |
|---|---|---|
| 매장 운영 상태가 안 보임 | TongssOrg 매장(Account) 레코드에 활성 상태 필드 | `[Top]` |
| 도입 현황 파악이 수작업 | 리스트뷰로 필터 가능한 도입/활성 상태 | `[Top]` |
| 매장별 맥락 없음 | 매장별 히스토리(등록 매뉴얼 수, 직원 학습 완료율) | `[Top]` |

### 박오너 (토스, 의사결정자)
| 페인포인트 | 기능 | 우선순위 |
|---|---|---|
| POS만으로 차별화 어려움 | (제품 전체가 답 — 별도 기능 아님) | — |
| MAU/이탈/부가서비스 지표 | 박세일즈 화면에서 자연 집계되는 지표 (신규 대시보드 아님) | Nice-to-have |

## 2. 스코프 (In / Out)

### In — 이번 5.5주 안에 만든다

**TongssApp (사장·직원용)**
- 매뉴얼 등록 (사진 + 짧은 텍스트, 서식 최소)
- 매뉴얼 뷰어 (직원용, 역할/상황별 진입)
- 오픈/마감 체크리스트 + 완료 여부 기록
- 재고 실사 입력 (수량 입력 → 부족 알림)
- 직원별 학습·체크리스트 완료 상태 (사장용 대시보드)

**TongssOrg (박세일즈용)**
- 매장(Account) Object + 도입/활성 상태 필드
- 매장별 히스토리 (등록 매뉴얼 수, 직원 학습 완료율 등 TongssApp에서 넘어온 데이터)
- 리스트뷰 기반 필터 (활성/방치 매장 구분)

**연동**
- TongssApp → TongssOrg 데이터 파이프라인 (05_DATA_CONTRACT 기준)

### Out — 이번엔 만들지 않는다

- ❌ 결제/POS 기능 (토스플레이스 영역)
- ❌ 고객관리(CRM/멤버십) — 도도포인트·캐시노트와 중복 (00_WHY §6)
- ❌ 발주 자동화, 원가·마진 계산 (Nice-to-have, 00_WHY 부록 B 참고용으로만 남김)
- ❌ 다점포 통합 대시보드 (1차 타깃은 개인 매장·소규모 브랜드)
- ❌ 박오너용 별도 지표 대시보드 (박세일즈 화면에서 자연 집계로 대체)
- ❌ 인수인계 메모, 발주 제안 등 00_WHY 부록 B의 나머지 기능 후보 전부

### 애매한 것 (Week 1에 팀이 결정)

- 매뉴얼에 카테고리/태그를 둘 것인가, 아니면 완전 무순서 리스트로 시작할 것인가
- 체크리스트 항목을 사장이 직접 만드는가, 기본 템플릿을 제공하는가
- `[확인필요]` 그 외 애매한 스코프는 발견되는 대로 여기 추가

## 3. 스코프 컷 우선순위 원칙

Week 3 중간 점검에서 반드시 뭔가 잘라야 한다. 그때 논쟁하지 않도록 지금 합의한다.

> **Demo Day 한 줄 시나리오(§0)에 기여하지 않는 기능부터 자른다.**

컷 순서 (위에서부터 먼저 자름):
1. Nice-to-have로 표시된 것
2. In 스코프 중 "구현은 됐지만 데모 흐름에 필수는 아닌" 디테일 (예: 매뉴얼 카테고리 분류, 세부 통계)
3. UX 완성도 (다듬는 것보다 흐름이 끊기지 않는 것이 우선)

**자르지 않는 것:** 한 줄 시나리오를 구성하는 최소 기능 (매뉴얼 등록 → 뷰어 → org 반영)

## 4. Demo Day 성공 기준 (상세)

| 기준 | 확인 방법 |
|---|---|
| 이대표가 매뉴얼을 등록한다 | TongssApp에서 실제 매뉴얼 1건 이상 등록 완료 |
| 김스태프가 TongssApp에서 본다 | 직원 화면에서 해당 매뉴얼 조회 + "다 봤어요" 체크 |
| 박세일즈가 org에서 확인한다 | TongssOrg 매장 레코드에 등록 매뉴얼 수·학습 완료율이 실제 데이터로 표시 |
| 전체 흐름이 실 데이터로 연결 | 더미 데이터 아닌, TongssApp에서 만든 데이터가 org까지 도달 |

이 네 가지가 Week 4 종료 조건이자 Demo Day 리허설의 체크리스트다.
